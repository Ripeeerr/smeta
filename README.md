# Смета

Веб-приложение для закупок небольшой компании. Сотрудники создают заявки, руководители согласуют расходы, закупщики выбирают поставщиков и фиксируют получение товаров.

## Возможности

- Рабочий обзор с бюджетом, резервами, расходами и очередью согласований.
- Заявки с несколькими позициями, вложениями, комментариями и историей действий.
- Четыре роли: сотрудник, руководитель отдела, закупщик, руководитель компании.
- Месячные бюджеты отделов. Согласование резервирует средства, отмена освобождает резерв.
- Предложения поставщиков и оформление закупки по согласованной цене.
- Частичная приёмка: закупка закрывается после получения всех позиций.
- Поиск, фильтры, пагинация, светлая и тёмная темы, мобильная навигация.

Приложение рассчитано на одну компанию. Учётные записи создаёт администратор. Публичной регистрации и банковских платежей нет. Оформление закупки фиксирует расход в бюджете; это управленческий учёт, а не подтверждение банковской оплаты. Если предложение дороже согласованной суммы, требуется новая заявка с актуальным расчётом.

## Стек

Сервер: Python 3.12, Django 5.2, Django REST Framework, PostgreSQL 17, uv. Интерфейс: React, TypeScript, Vite, TanStack Query, Bun. Проверки: pytest, Ruff, Bun Test и Playwright.

## Быстрый запуск

Нужны Docker с Compose, Bun 1.4.4 и uv 0.13.7.

```bash
bun scripts/setup.mjs
docker compose up --build -d
docker compose exec api uv run --frozen manage.py seed_demo
```

Приложение: <http://localhost:5173>. API: <http://localhost:8000/api/health/>.

`setup.mjs` создаёт `.env` с отдельными случайными паролями базы и демонстрационных пользователей. Существующий `.env` сохраняется. Он не попадает в Git или Docker-образы.

Демонстрационные логины:

| Логин | Роль |
| --- | --- |
| `director` | Руководитель компании, все отделы |
| `manager` | Руководитель отдела продаж |
| `buyer` | Закупщик |
| `employee` | Сотрудник отдела продаж |
| `accountant` | Сотрудник бухгалтерии |
| `engineer` | Сотрудник ИТ |

Пароль для этих пользователей — значение `DEMO_PASSWORD` в локальном `.env`. Наполнение повторно не сбрасывает пользователей и закупки. Команда доступна только в режиме разработки.

## Разработка без контейнеров приложения

```bash
bun scripts/setup.mjs
docker compose up db -d
cd backend
uv sync --frozen
uv run manage.py migrate
uv run manage.py seed_demo
uv run manage.py runserver
```

В другом терминале:

```bash
cd frontend
bun install --frozen-lockfile
bun run dev
```

Новые зависимости устанавливаются через `uv add` или `bun add`. Python-команды запускаются через `uv run`.

## Проверки

```bash
cd backend
uv run ruff check .
uv run ruff format --check .
uv run manage.py makemigrations --check --dry-run
uv run pytest -q
```

```bash
cd frontend
bun run format:check
bun run build
bun run test
```

Для E2E создайте отдельную базу из корня репозитория:

```bash
docker compose exec db psql -U smeta -d postgres -c 'CREATE DATABASE smeta_e2e;'
cd frontend
bunx playwright install chromium
bun run test:e2e
```

Адрес `E2E_DATABASE_URL` создаётся в `.env` при первоначальной настройке. Конфигурация тестов требует имя базы с окончанием `_e2e`. Тесты поднимают свои серверы на портах 8001 и 5174, мигрируют отдельную базу и создают демонстрационные данные. При необходимости другой установленный Chromium можно указать переменной `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

## Безопасность и данные

Сессия хранится в HttpOnly-cookie. Изменяющие запросы, включая вход и выход, защищены CSRF. Права проверяются на сервере, а изменения бюджета проходят через транзакции и блокировки строк PostgreSQL. Ограничения базы запрещают отрицательные суммы и выход расходов с резервами за лимит.

Вложения скачиваются через авторизованный endpoint с проверкой доступа к заявке, принудительным скачиванием и `nosniff`. Поддерживаются PDF, PNG и JPEG до 10 МБ, до пяти файлов на заявку. Содержимое файлов не отображается как HTML. Файлы сохраняются под случайными именами вне публичного каталога.

Compose предназначен для локальной разработки: порты привязаны к localhost, включены Vite и Django runserver. Перед размещением необходимы отдельная конфигурация production, HTTPS, собственные пользователи, резервное копирование и постоянное хранилище вложений. Не публикуйте `.env` и не включайте демонстрационные данные в рабочую систему.

## Git workflow

`feature/*` — отдельные изменения, `develop` — интеграция, `release/*` — подготовка версии, `main` — проверенные релизы, `hotfix/*` — срочные исправления. Коммиты используют префиксы `feat:`, `fix:`, `test:`, `chore:`, `docs:` и `build:` с описаниями на русском.
